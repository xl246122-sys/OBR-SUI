## 0. 项目目标、治理边界与状态

### 0.1 目标及不能做的事
- 用户是出资投资人；系统在**预先批准、不可自行放宽**的风险边界内全天候自主执行：数据采集、市场识别、放量突破、限价买入、退出、监控、恢复、日报；尽量不需要用户参与日常技术判断。
- **唯一交易资产：币安现货 SUI/USDT；只做向上放量突破、上涨趋势延续/二次放量；不做抄底、超跌反弹、下跌加仓、合约、杠杆、借贷、做空、其他币种交易。** BTC/USDT 只能用于大盘判断、相关性及风险过滤，不下 BTC 单。
- 不能保证盈利、最低买价、限价单成交或止损恰好亏 1%；追求扣除全部可计量成本后的样本外风险调整收益。
- **默认模式严格为 `RESEARCH` 或 `PAPER`；禁止初始化为 `LIVE`。** 首次接入真实资金、提高仓位/亏损限额、变更重大权限或解除严重安全冻结，需要用户明确批准。聊天中的“同意技术方向”不代表实盘授权。
- 研究训练可进化，但**交易策略不能在没有验证与审计的情况下在线自我改写**；不会允许任何学习模块自动放宽风控、重写密钥权限或启用新交易对。

### 0.2 已讨论并基本认可 / 仍待验证
| 类别 | 已认可方向 | 仍待验证 / 不视为确定事实 |
|---|---|---|
| 交易策略 | 自适应趋势 + 全天放量突破；BTC辅助 | 趋势分类、特征权重、突破阈值、是否提前入场 |
| 风险退出 | 成交加权买入均价下跌1%触发止损；严守仓位保护 | 实际最终亏损、极端波动成交、账户风控阈值 |
| 止盈 | C1净收益+1.5%固定、C2上涨分批网格、C3自适应混合，**三者公平回测择优** | 哪个实盘最好、网格档位、仓位比例、追踪参数 |

## 1. 实际硬件和职责分工

**本地研究电脑**：Windows 11；Intel Core i5-13400F；16GB RAM；1TB NVMe SSD；MSI RTX 5060 8GB。用于历史数据下载、清洗、压缩存储、概率模型训练/调参、回测、样本外验证、报告、签名打包。GPU 为候选加速资源，V1不强制用神经网络。

**日本服务器**：一台 Ubuntu Linux，2 vCPU / 2GB RAM / 40GB 磁盘。负责 7×24 WebSocket、特征更新、轻量模型推断、订单路由、独立风控、交易记录、告警与守护。**无训练任务，不储存全部历史数据，不依赖Windows开机**。

**Android手机**：Kotlin + Jetpack Compose 原生监控端，展示交易、风控、扫描、延迟、日志摘要、通知，提供认证保护的暂停新开仓和紧急控制；不存交易所API私钥，不承担订单执行。App关闭不影响服务器。

**存储推荐**：本地 `Parquet + DuckDB`（研究仓与快照）和模型制品仓；服务器 `SQLite WAL`（订单/仓位/审计/事件）+ 受限内存缓存 + 聚合行情短期滚动文件。不得在 2GB 环境部署 Kafka/Kubernetes/大型时序数据库或完整 GPU 训练。

## 2. F-01｜行情采集、计算时钟、信号扫描
- 实时订阅：`SUIUSDT @trade` 或 `@aggTrade`、`@bookTicker`、`@depth10@100ms`、`@kline_1m/_5m/_15m/_1h`、`BTCUSDT` K线/成交/最优价、账户 `executionReport`、REST 按需查询。
- 严格区分已完成收盘数据与实时未收盘数据；记录交易所事件 UTC、接收 UTC、单调时钟延迟、更新 ID、数据质量标志。

## 3. A-01｜市场状态数学模型
- 输出 `regime ∈ {UP_TREND, CONSOLIDATION, DOWN_TREND, HIGH_VOLATILITY, DATA_UNHEALTHY}`、强度、置信度、数据版本、UTC 时间、有效期、`allow_new_entry`。

## 4. A-02｜向上放量突破成功概率
- 已收盘 5m K 线突破前 20 根完整 5m K 线最高价；三障碍标签（净 +1.5% WIN / 入场均价 -1% STOP / 3h TIMEOUT），训练校准三分类模型 `p_win + p_stop + p_timeout = 1`。

## 5. B-01｜智能限价单与微观结构执行
- 受价格上限保护的 `LIMIT` 候选；基于盘口回放与模拟订单校准成交概率与逆向选择 `markout(1s,5s,30s,60s)`；唯一 `clientOrderId`；部分成交立即安排保护。

## 6. C-01｜三种退出候选模型与同一止损规则
- 止损基线：`stop_trigger = actual_fill_weighted_entry_price * 0.99`。
- 三策略统一对照回测：C1（扣费净收益 +1.5% 全额卖出）、C2（上涨方向 3-4 档分批 + 追踪）、C3（自适应状态混合）。

## 7. D-01｜唯一的自主决策权与状态机
- 状态机：`BOOT -> SYNCING -> READY_NO_POSITION -> SIGNAL_CANDIDATE -> RISK_CHECK -> ORDER_SUBMITTED -> ORDER_UNKNOWN | PARTIALLY_FILLED | FILLED -> PROTECTION_PENDING -> PROTECTED -> EXITING -> FLAT`，以及任意时刻可转入 `ENTRY_FROZEN` 或 `SECURITY_LOCKDOWN`。

## 8. R-01｜独立资金与订单风控（高于策略）
- 仅 `SUIUSDT` 现货；候选风险预算（未获实盘授权）：单笔账户风险 ≤ 0.25% 权益、单次资金占用 ≤ 10% 权益、滚动 24h 损失达 1% 暂停新开仓。

## 9. F-02｜整套系统运行守护与自动恢复
- `systemd` + 5s 业务心跳 + 30s 卡死检测 + 崩溃 10s 内开始重启 + 23h WebSocket 提前轮换；重启进入 `SYNCING` 对账后才可恢复。

## 10. S-01｜服务器安全总管
- SSH/UFW/Fail2Ban/最小权限/文件校验/异常出站监控；INFO/HIGH/CRITICAL 分级响应；独立外部心跳探测云服务器失联。

## 11. E-01｜研究仓、同步、模型版本与发布
- Windows 离线训练与 `ModelManifest` 签名打包；云端 `SHADOW -> PAPER` 原子发布与自动回滚；已有持仓锁定原退出模型版本。

## 12. G-01 / G-02｜Android原生APP、监控与推送
- 纯 `Kotlin + Jetpack Compose + MVVM + Room + WorkManager + Keystore + FCM`；前台原生弹窗 + 后台系统通知必需。
